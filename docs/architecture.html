Factory Inventory Management System

Architecture overview — Vue 3 frontend, FastAPI backend, in-memory mock data (no database)

Tech Stack

Frontend

Vue 3 + Vite

  • Composition API, module-scoped composables for shared state (no Vuex/Pinia)
  • vue-router (6 routes) + axios for HTTP
  • 7 views, 9 shared components
localhost:3000
Backend

Python FastAPI

  • Single-file app (main.py), 14 REST endpoints
  • Pydantic models for request/response validation
  • CORS wide open (dev only)
localhost:8001
Data

In-memory JSON

  • 7 JSON fixture files in server/data/
  • Loaded once into Python lists/dicts at import time
  • No persistence — no database, no writes back to disk
no DB

System Diagram

Request Lifecycle — Example: Inventory page with warehouse + category filters

1

Filter state read

Inventory.vue calls useFilters().getCurrentFilters() — reads shared singleton refs (selectedLocation, selectedCategory, …) and maps them to { warehouse, category, status, month }.

2

API call

api.getInventory(filters) in client/src/api.js builds a URLSearchParams (omitting any value equal to "all") and issues axios.get('http://localhost:8001/api/inventory?...').

3

FastAPI routing

Request hits GET /api/inventory in server/main.py, bound to get_inventory(warehouse=None, category=None).

4

In-memory filtering

apply_filters(inventory_items, warehouse, category) filters the list already loaded into memory by mock_data.py from inventory.json.

5

Validation & serialization

FastAPI coerces the filtered list into List[InventoryItem] (Pydantic), validating field types and serializing to JSON.

6

Render

Axios resolves in api.js; the view assigns response.data to a local ref, and Vue's reactivity re-renders the table.

The same pattern — composable → api.js → FastAPI route → filter helper → in-memory list → Pydantic model → axios → view ref — is repeated for Dashboard, Orders, Demand, Spending, and Reports.

Filter System

A single FilterBar.vue is rendered globally in App.vue, above every routed view. Its four selects bind to module-level singleton refs in composables/useFilters.js, so every view reacts to the same shared state without props, events, or a central store.
